# Configuration: files, settings and changes

[Start here](../README.md) · [Setup walkthrough](quickstart.md) · [Troubleshooting](recovery.md)

## Which files do I manage?

For a default installation, `configure` and `apply` create everything the toolkit needs. Run commands from the repository directory on the Ubuntu host.

| File or directory | Purpose | What you do |
| --- | --- | --- |
| `.f2b-toolkit/plan.json` | Proposed policy; created by `configure`, ignored by Git | Review and edit settings here |
| `/etc/fail2ban/jail.d/90-toolkit-sshd.local` | Live SSH jail; generated by `apply`, mode 0640 | Inspect with `sudo cat /etc/fail2ban/jail.d/90-toolkit-sshd.local`; update through the plan |
| `/etc/fail2ban/jail.conf`, `filter.d/sshd.conf`, `action.d/ufw.conf` | Package defaults, SSH matching and firewall action | Use the installed package definitions; no edits needed for this workflow |
| `/etc/fail2ban/jail.local`, other `jail.d/*` files | Existing administrator/package policy, if present | Review conflicts before adoption; do not copy a full `jail.conf` into `jail.local` |
| `templates/sshd.local.tpl` | Repository template used by the renderer | No end-user edit needed |
| `/var/lib/f2b-toolkit/` | Private deployment and recovery data | Retain it; do not hand-edit it to bypass an error |

The plan is input to the toolkit, not a file Fail2Ban reads directly. Saving an edit changes nothing on the running server until `apply` succeeds.

## Settings and their consequences

| Plan field / configure option | Default and accepted values | Meaning and consequence |
| --- | --- | --- |
| `trusted_ips` / `--trusted-ip` | Required IPv4/IPv6 addresses or CIDRs; repeat the flag | These sources bypass this jail's bans. Missing your address risks lockout; broad ranges exempt more clients. Universal ranges are refused. |
| `ports` / `--port` | Detected with `sshd -T`; integers 1–65535; repeat the flag | Must match all configured SSH ports during apply. Does not change SSH listeners or limit the UFW ban to these ports. |
| `backend` / `--backend` | `systemd`; also accepts `polling` | Use the journal or `/var/log/auth.log`, respectively. The wrong source can leave failures undetected. |
| `bantime` / `--bantime` | 600 seconds; 60–604800 | How long a source remains banned. A longer value also prolongs an accidental lockout. |
| `findtime` / `--findtime` | 600 seconds; 60–86400 | Window in which matching failures accumulate. A longer window can catch slower attempts and more legitimate mistakes. |
| `maxretry` / `--maxretry` | 5; 1–100 | Matching failures needed for a ban. Lower values ban sooner and tolerate fewer mistakes. |

The template adds loopback addresses to `ignoreip`, ignores the server's own addresses, uses normal SSH matching and numerical addresses, and disables increasing ban durations. It explicitly selects `action = ufw`. That action's default rule covers the banned source across ports; see the [upstream UFW action](https://github.com/fail2ban/fail2ban/blob/1.0.2/config/action.d/ufw.conf). Inspect your installed action if package behavior differs.

With `systemd`, the generated journal match is `_SYSTEMD_UNIT=ssh.service + _COMM=sshd` and no file log path is generated. With `polling`, the path is fixed to `/var/log/auth.log` and the journal match is cleared. Arbitrary log paths, custom filters, extra jails and other actions are not configurable through this plan.

## Edit the policy

To change one value while keeping the others, edit the existing plan:

```bash
sudo cp .f2b-toolkit/plan.json .f2b-toolkit/plan.before-edit.json
sudo nano .f2b-toolkit/plan.json
```

For example, change `"bantime": 600` to `"bantime": 1800` for a thirty-minute ban. In nano, save with Ctrl+O, Enter, then exit with Ctrl+X. Use another editor if nano is unavailable. Preserve the JSON structure, all keys, double quotes and numeric types; JSON does not allow comments or trailing commas.

This is the expected shape, **with a documentation-only address that you must replace**:

```json
{
  "version": 1,
  "settings": {
    "trusted_ips": ["192.0.2.10/32"],
    "ports": [22],
    "backend": "systemd",
    "bantime": 1800,
    "findtime": 600,
    "maxretry": 5
  }
}
```

Validate the JSON structure, review the generated difference, and deploy:

```bash
sudo python3 -m json.tool .f2b-toolkit/plan.json
sudo python3 bin/f2b-tool plan
sudo python3 bin/f2b-tool apply
sudo python3 bin/f2b-tool status
```

`json.tool` only checks JSON syntax. `plan` checks supported fields/values and ownership/conflicts; `apply` checks the host and parses the complete Fail2Ban configuration. Repeat the [external verification](quickstart.md#5-verify-monitoring-and-actual-blocking) after a policy change.

Alternatively, generate a whole replacement plan with explicit options. Replace the example address and port before use:

```bash
sudo python3 bin/f2b-tool configure \
  --trusted-ip 192.0.2.10 \
  --port 22 \
  --backend systemd \
  --bantime 1800 --findtime 600 --maxretry 5
sudo python3 bin/f2b-tool plan
sudo python3 bin/f2b-tool apply
sudo python3 bin/f2b-tool status
```

Repeat `--trusted-ip` and `--port` for every required value. **Configure replaces the plan instead of merging with it.** Omitted timings/backend reset to defaults; omitted ports are detected again. To change only the backend of an existing custom policy, edit the plan rather than running a partial configure command.

If you discard an un-applied edit, restore your local copy with `sudo cp .f2b-toolkit/plan.before-edit.json .f2b-toolkit/plan.json`. For an already deployed change, use [rollback](recovery.md#restore-the-previous-deployment). Rollback restores server state, not this local plan; reconcile the plan before the next apply.

## Choose another plan location

The default path is relative to your current directory. A different working directory can select a different or nonexistent plan. To choose an absolute path, put `--plan` **before** the subcommand and use it consistently:

```bash
sudo python3 bin/f2b-tool --plan /root/ssh-plan.json configure
sudo python3 bin/f2b-tool --plan /root/ssh-plan.json plan
sudo python3 bin/f2b-tool --plan /root/ssh-plan.json apply
```

Keep plans private: they contain trusted network addresses. The default directory is Git-ignored; custom paths inside a checkout may not be.

## Existing policy and recovery files

The toolkit refuses administrator SSH, global-default or include overrides in `jail.local` and jail drop-ins. It permits Ubuntu's small `defaults-debian.conf` only when its contents match recognized package settings. Other service sections remain in place and participate in validation.

If a conflict is reported, review the named file alongside your intended policy. An existing customized installation may require manual migration; this is not an automatic merge tool. Use [conflict troubleshooting](recovery.md#existing-configuration-or-managed-file-conflict), keeping unrelated production policy intact. The [upstream jail manual](https://github.com/fail2ban/fail2ban/blob/1.0.2/man/jail.conf.5) explains configuration loading.

Recovery data lives here:

```text
/var/lib/f2b-toolkit/                  Root-owned, mode 0700
  lock                               Coordinates toolkit operations
  state.json                         Current deployment ID and content digest
  pending.json                       Present during deployment/recovery
  deployments/<deployment-id>/
    record.json                      Prior/next content, service state, prior state
```

Backups remain after rollback; this version has no automatic cleanup. Direct edits to the managed jail cause digest checks to fail, protecting those edits from being silently overwritten. An untracked file at the target path is also refused. Avoid concurrent edits through other management tools: the toolkit lock coordinates only its own processes.

## Command reference

Run `python3 bin/f2b-tool --help` or `python3 bin/f2b-tool configure --help` for options.

| Command | Effect |
| --- | --- |
| `doctor` | Inspect prerequisites without changing settings |
| `install-deps` | Install Fail2Ban and journal bindings using apt; confirmation required |
| `configure` | Write/replace the local plan |
| `plan` | Preview the managed file difference |
| `apply` | Validate, save recovery data, deploy and restart Fail2Ban; confirmation required |
| `status` | Show reported service/jail/firewall status |
| `rollback` | Restore the previous managed file and service state; confirmation required |

Use sudo for server operations. `install-deps`, `apply` and `rollback` accept `--yes` after the command for reviewed automation; otherwise they require an interactive confirmation. This does not bypass validation. Invoking the entry point with `python3` avoids depending on executable permissions in downloaded archives.
